🧬 HMM Homologue Finder

A reproducible, one-command pipeline that discovers distant homologues of a protein family across public phage/viral databases — including genes standard annotation misses — and returns ORF-validated sequences, evidence tables, a calibrated profile HMM, alignments, a phylogenetic tree, synteny maps, and a publication-ready package. You provide one seed FASTA; it does the rest.

What it does

It builds a profile HMM from your seed sequences, searches a set of public databases (translating genome databases in all six reading frames so it can reach unannotated genes), reconstructs and validates the exact ORF each hit came from (frame/strand-correct, no internal stop codons, in a genuine coding locus), then re-seeds the search with the discovered sequences and repeats until the family stops growing (convergence). It calibrates the score thresholds against built-in positive and negative controls, then clusters the homologues, aligns them, builds an ML tree, draws synteny figures, and assembles everything — with a full methods record and provenance — into a labelled folder.
It is general: point --fasta at any protein family's seed FASTA. The bundled example is a phage protein, but nothing is hard-wired to it.
Finds the unfindable. Six-frame translation + ORF validation recovers homologues encoded antisense or out-of-frame to predicted genes — exactly what BLAST-on-annotation misses.
Honest by construction. Every hit carries its evidence (coords, ORF stats, provenance); thresholds are calibrated with controls; nothing is taken on faith.
Walk-away. One command, no prompts in unattended mode, can't hang on NCBI, resumable, keeps the machine awake.
Reproducible. Pinned environment, recorded tool versions, database URLs + SHA-256 + access dates, fixed RNG seeds — all in run_manifest.json + METHODS.md.

Install (one-time)

The only thing you install by hand is conda (via Miniforge). Then setup.sh creates the hmm-discovery environment with every tool. No Docker. Runs on Linux, macOS, and Windows (inside WSL2 — the bioinformatics tools have no native Windows builds).

macOS / Linux / WSL2

bash setup.sh        # creates the hmm-discovery env, installs all tools, verifies
Apple Silicon (M1/M2/M3): several tools have no native osx-arm64 conda build. setup.sh auto-sets CONDA_SUBDIR=osx-64 so the env builds for x86-64 under Rosetta 2 (install once with softwareupdate --install-rosetta --agree-to-license). Override by exporting CONDA_SUBDIR yourself first.
Windows: install WSL2 once (wsl --install -d Ubuntu in an Administrator PowerShell, then reboot), open Ubuntu, and run bash setup.sh. Or double-click run.bat, which launches the tool inside WSL2 for you.

Quick start

Easiest — guided wizard

bash start.sh
Walks you through the seed FASTA, run mode, databases, and options, then launches the run. On macOS you can instead double-click scripts/Run HMM Homologue Finder.command in Finder.

Interactive — drag your FASTA in

bash run.sh
#   seed FASTA >   (drag your .fasta into the terminal, press Enter)
run.sh activates the environment, verifies the software, then prompts for your seed.

Explicit — fully unattended

conda activate hmm-discovery
python3 scripts/hmm_finder.py --fasta my_seeds.faa --name my_protein --cpu 8
The only required argument is --fasta. With no TTY (cron/nohup/pipe) it never prompts — it uses the full default database set and runs to completion.
Always try a self-test first on a new machine or new protein — minutes, not hours: 
python3 scripts/hmm_finder.py --fasta my_seeds.faa --smoke --name my_protein

How it works (methods)

1
Build the HMM. Align seeds with MAFFT (accuracy-first L-INS-i, --localpair --maxiterate 1000, for ≤500 seqs; else --auto), trim with trimAl (automated1), build the profile with hmmbuild, and require the model to recover ≥70% of its own seeds before proceeding.
2
Search. hmmsearch at E ≤ 1×10⁻⁵ over the selected databases. Each download is SHA-256-checked with its URL + access date recorded. Nucleotide databases are translated in all six frames into stop-to-stop ORFs (min 30 aa); large DBs are chunked with seqkit and run in parallel.
3
Extract & validate each hit. The ORF is reconstructed from genomic coordinates (1-based, strand/frame-correct); the domain is delimited by the HMM envelope (--domtblout). Recorded: ORF/domain length, coverage, internal-stop count (must be 0), and Prodigal overlap. A hit passes if it has no internal stops and sits in a coding locus. Protein-DB hits are captured by accession. Both NT and AA are exported with a per-hit evidence table.
4
Iterate to convergence. Unique validated domains re-seed the next round. Iteration stops early when the unique-hit count changes <5% and the HMM length changes <3 between rounds (or a round finds nothing). The stopping reason is recorded.
5
Calibrate thresholds. Positive (seed self-test) + negative (composition-matched shuffled seeds, plus optional unrelated proteomes) controls give per-run sensitivity, specificity, and false-positive rate at the strict bit threshold. Details ↓
6
Characterise. CD-HIT clustering (40% id, 80% cov); accuracy-first MAFFT alignment of the unique homologues (a first-class deliverable: full + trimmed MSA, stats, ClustalX figure); trimAl → IQ-TREE ML tree (ModelFinder, 1000 ultrafast bootstrap, fixed seed) with the seeds placed and marked SEED_*; clinker synteny + real-sequence GenBank neighbourhoods; MEME/FIMO motifs; GFF3 tracks.
7
Package. Everything is assembled into a labelled folder with report.html, METHODS.md, and machine-readable run_manifest.json (parameters, provenance, tool versions, calibration, stop reason).
The most-complete round (after convergence, the refined final round) is the canonical set used for the figures, the published profile HMM, and the main paper table — so tables and figures always describe the same homolog set.

Calibration & controls

The bit-score thresholds that tier hits (strict 45, moderate 30) are calibrated per run on the profile HMM, so you can state that hits above threshold aren't an artefact of amino-acid composition or generic similarity:
  • Positive control — the seed set itself. Sensitivity = fraction of seeds recovered at the strict threshold (expected ≈ 1.0).
  • Negative controls — composition-matched shuffled seeds (always available, no network), plus, with --download-controls, curated reviewed Swiss-Prot fungi/mammalian/archaea proteomes. False-positive rate = fraction of negatives scoring ≥ strict.
Results are written to controls/control_report.json + controls_summary.csv and summarised in run_manifest.json (threshold_calibration) and METHODS.md. Disable with --no-controls.

Reproducibility

The whole workflow runs from one command and records everything needed to reproduce it:
  • Pinned environment — environment.lock.yml (exact builds); environment.yml for fresh solves.
  • Per-run provenance — run_manifest.json + METHODS.md: command line, parameters, code git commit, conda env, Python version, input SHA-256, per-database URLs + SHA-256 + access dates, per-iteration counts, stop reason, calibration, and tool versions.
  • Determinism — IQ-TREE runs with a fixed seed (-seed 12345); MAFFT/trimAl/CD-HIT are deterministic; sorted iteration throughout.
Reproducibility is delivered by the pinned environment + recorded provenance, not containers (no Docker by design).

Troubleshooting

conda: command not found
Install Miniforge, then close and reopen the terminal. On macOS/Linux: curl -L -O "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname -s)-$(uname -m).sh" && bash Miniforge3-*.sh, then re-run bash setup.sh.
It exits: "The profile HMM failed self-validation"
Too few seeds are recovered by the model built from them (the --min-recovery 0.70 gate). It almost always means the seeds aren't one coherent family (e.g. a broad label like "endolysin" spanning unrelated proteins). Fixes: use a tighter single-family seed set, drop outliers, or relax the recovery requirement only for a deliberately divergent superfamily.
Apple Silicon: conda can't solve / tools won't install
Bioconda tools have no osx-arm64 build. setup.sh sets CONDA_SUBDIR=osx-64 automatically; ensure Rosetta 2 is installed (softwareupdate --install-rosetta --agree-to-license). To force it for a manual env, export CONDA_SUBDIR=osx-64 before creating it.
"more threads than CPU cores available" (IQ-TREE)
Already handled: --cpu is auto-clamped to the available core count. If you see this, you're on an old build — update, or pass a smaller --cpu.
No internet / NCBI is down
Run with --no-annotate (or simply provide no email) — six-frame discovery is unaffected; only NCBI organism names and protein-DB hit sequences are skipped. The run never sends a placeholder address and never hangs on the network.
Disk space
Databases are cached once in ~/.cache/hmm-homologue-finder (several GB across the full set). Inspect or prune with python3 scripts/manage_cache.py. Keep ~20 GB free for a full run.

How to cite

Cite this tool (see CITATION.cff) plus the tools and databases a run actually used — the exact citation list for your run is written into METHODS.md ("Citations") and CITATIONS.md. Core methods: HMMER (Eddy 2011), MAFFT (Katoh & Standley 2013), trimAl (Capella-Gutiérrez et al. 2009), Prodigal (Hyatt et al. 2010), CD-HIT (Fu et al. 2012), IQ-TREE 2 + ModelFinder + UFBoot2 (Minh/Kalyaanamoorthy/Hoang), MEME (Bailey et al. 2009), clinker (Gilchrist & Chooi 2021), Biopython (Cock et al. 2009), and each database's reference.
